Elements. Plain HTML, styled.

The base layer styles every HTML element without a class. Write the right element first, and add an sd- class only when the element cannot say enough.

Principles

  • Semantics first. Headings, lists, tables, form controls, details, dialog and popover look right as written, so the markup stays plain HTML.
  • Classes win. The base layer comes after Tailwind's reset, and any sd- class or utility sits in a later layer, so it overrides the base.
  • Native before custom. A <dialog>, a popover or <details> gets its behavior from the browser. Signal adds the look and, for popovers, placement.
  • Square and flat. Inputs, checkboxes and media have square corners and no shadows.

Use it for

  • Articles, docs and settings pages where plain markup is enough.
  • Forms with native controls: every input type, select, textarea, checkbox, radio, switch, range and file.
  • Anywhere you would rather write a table than a component.

Leave it out when

  • A state the element cannot express, such as a tone or a selected row. Use the component and its data-tone or ARIA state.
  • Building your own dropdown, tooltip, modal or tabs. Use the native element plus Signal.
  • Adding an sd- class out of habit. The unclassed element is already styled.
