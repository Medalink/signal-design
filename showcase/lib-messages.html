Messages, composer, reactions, banners, files and link cards. Nothing in them assumes chat, so the same parts build a comment thread, an activity feed or an inbox.

Generic pieces for anything with people and messages: chat, comments, activity, inboxes. The chat example puts them together.

Principles

  • Color identifies, never decorates. A message edge takes an author or role color through --edge; your own messages get a grey edge. Pending, failed and selected messages change the edge or the fill in a fixed order.
  • Presence is a square. data-status puts online, away, busy or offline on the avatar corner. Set --sd-ring to the panel color so the ring matches.
  • Every name is colored. An author, an @mention, a quoted author and the reply bar take the person's color through --who, and fall back to extra. Text only, never a fill.
  • State sits in attributes. data-own, data-selected, data-pending, data-failed, data-grouped, data-reply, data-editing and data-mention restyle a message. Your code sets them, including grouping (same author within a few minutes).
  • Live values hold still between changes. The level meter lights bars up to --level, fades for 120ms when the value moves, and rests otherwise.
  • Unknown stays visible. A link card has data-blocked and aria-busy="true" states, so a blocked or loading link says so.

Use it for

  • Chat, comment threads, activity feeds and inboxes.
  • Call grids with sd-tiles, which show speaking, muted and raised-hand states.
  • Composers that grow with the text and send on Enter.

Leave it out when

  • Sending, receiving or storing messages. These parts style state. Transport and data are yours.
  • Author colors that do not name an author or a role. Color is for meaning.
  • Hand-rolled reaction or poll toggles. Use sd-reactions and sd-poll.
