Tokens. Roles, not values.

Every color, size and duration is a token. Your markup reads roles such as --sd-fg and --sd-danger, so a theme change needs no rebuild.

Principles

  • Name the job, not the hue. Use text-danger, never text-pink or a hex value. Paper deepens the signal colors, and a hard-coded value would not follow.
  • Color means something. Only status and focus are colored. Everything else, navigation included, is black, white and grey.
  • Text stays readable. Every text role meets 4.5:1 on every surface of its theme. The contrast block below shows each ratio live.
  • Two faces, two weights. One text face in regular and medium, and Source Code Pro for code. The text face is SF Pro (Segoe UI on Windows) unless the font picker swaps it. Set a family through font-sans or var(--sd-font-sans), never by name. Prose read at length, such as a manuscript, is the one exception: font-reading.
  • Motion marks a state change. Transitions run 120 to 200ms on ease-out. Nothing loops for decoration.

Use it for

  • Choosing a color, size or duration for your own component.
  • Checking a theme before you ship. Switch ink, graphite and paper in the bar above.
  • Reading how a role looks: the swatches and ratios below follow the current theme.

Leave it out when

  • Reaching for a brand hue. Color is reserved for status, so Signal has no decorative colors.
  • Hard-coding a hex value or a pixel size. Themes and the type scale would stop applying.
  • Adding a shadow, glow or gradient. Surfaces are flat and use hairlines only.

Tokens

Raw values live in @theme and become utilities. Semantic roles switch per theme at runtime, so bg-canvas or text-fg-muted follow the theme with no rebuild. Values below are read live from the current theme.

Hard rules

  1. Square corners everywhere, avatars and checkboxes included.
  2. Flat surfaces. No glass, grain, glow or shadow. Fades are for borders and edges only.
  3. Color is for important things: risk, status, success, focus. Everything else is black, white and grey, navigation included.
  4. Motion on state change only: 120–200ms transitions and a one-pass hover shimmer. The rain moves only while work runs or when the reader turns it on.
  5. Minimal by default, detail on expand.
  6. SF Pro for text in regular and medium; Source Code Pro for code. The font picker swaps the text face.

Signals

The only saturated colors. Each one has a job. Use the role (text-danger), not the hue (text-pink), so paper (the light theme) can deepen it.

Greys

Ink is the shipped Signal ramp: cool and near-black. Graphite is the original ramp from the spec table. The ink theme uses the first, the graphite theme the second.

Spec vs shipped

The original spec table and the shipped stylesheet disagree. Ink, the shipped ramp, is the canonical default. Graphite keeps the spec values as an optional theme.

Any element can carry data-theme to theme its own subtree. Paper deepens the signal colors so they keep their contrast on white. auto picks ink, or paper when the OS asks for light.

Contrast on canvas

WCAG ratio of each text role against the current canvas. Body text needs 4.5. Every text role, fg-faint included, reaches it on the canvas, surface and raised fills of all three themes, so none of them is limited to decoration.

Type scale

text-3xs … text-5xl, each with its line height built in (--text-*) · text-base (16px) for body, text-sm for meta, text-2xs uppercase for labels, text-3xl for display · nothing below text-3xs (12px)

Fonts

data-font sets the text face of a subtree, or of the page on <html>. Code stays in Source Code Pro. Pick the page font under Settings in the bar above.
